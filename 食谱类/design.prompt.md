# 食谱类一览图设计语言 v0 — Recipe Card References

> 输入：单道菜食谱结构化信息。
> 输出：1920×1080 横版单文件 HTML，用于食谱模板风格参考。

## 目标

把一道菜做成一张可分享、可照做、可截图的菜谱卡片。食物照片是第一视觉锚，食材、调料、用量和烹饪方法必须清晰可读。

## 固定要求

- 简单菜画布逻辑尺寸固定为 `1920px × 1080px`。
- 复杂菜固定宽度 `1920px`，允许 `height:auto` 纵向延展成长图。
- HTML 必须是完整单文件，CSS 内联在 `<style>`。
- 可以引用本地图片资产，路径相对样例 HTML，例如 `assets/tomato-egg.png`。
- 不引入外部脚本、字体或远程图片。
- 必须包含：
  - 菜名
  - 菜肴主图
  - 一句风味描述
  - 份量、耗时、难度
  - 食材清单和用量
  - 调料清单和用量
  - 烹饪方法/步骤
  - 关键技巧或避坑提示

## 复杂度自适应

当菜谱满足任一条件时，不要强行塞进 1080px 单屏，应切换为长图：

- 食材数量超过 8 项。
- 调料数量超过 6 项。
- 步骤数量超过 6 步。
- 存在多个阶段：泡发、焯水、吊汤、炖煮、蒸制、收汁、冷藏、醒发等。
- 需要展示过程态图片或小白检查点。

长图结构建议：

1. 第一屏：成品主图、菜名、风味描述、份量、耗时、难度、核心提示。
2. 食材分组：按主料、辅料、汤底、调味、预处理等分组。
3. 过程态图示：每张图对应一个“看到这样就对了”的检查点。
4. 阶段步骤：按烹饪阶段拆分，不把复杂步骤写成长段。
5. 小白检查点：用看、闻、摸、尝等状态判断语言。

## 过程态图片

复杂菜谱可以包含步骤图或状态图，优先使用真实摄影感 AI 小图。过程态图不是装饰，必须解释一个判断：

- 糖色：浅琥珀、深琥珀、过焦发黑。
- 肉类熟度：三分、五分、七分、全熟的剖面。
- 收汁：汤汁能挂勺、锅底出现清晰划痕。
- 油温：筷子周围小泡、食材下锅冒泡速度。
- 泡发：干货完全展开、无硬芯。
- 炖汤：汤色清亮、浮沫撇净、微沸而不翻滚。

每张过程图旁边必须写：

- 当前阶段名称。
- 正确状态描述。
- 失败预警或下一步动作。

## 画布 CSS 基线

```css
* { box-sizing: border-box; }
html, body {
  width: 100%;
  height: 100%;
  margin: 0;
  background: #e5e5ea;
}
body { position: relative; }
.canvas {
  --scale: min(calc(100vw / 1920px), calc(100vh / 1080px));
  position: absolute;
  top: 0;
  left: 0;
  width: 1920px;
  height: 1080px;
  transform-origin: 0 0;
  transform:
    translate(
      calc((100vw - 1920px * var(--scale)) / 2),
      calc((100vh - 1080px * var(--scale)) / 2)
    )
    scale(var(--scale));
}
body.snapshot .canvas {
  transform: none;
  position: static;
}
```

## 四种参考风格

### 1. 小红书风

- 气质：温暖、明亮、生活感、适合分享。
- 适用：家常菜、早餐、甜品、减脂餐。
- 构图：大主图 + 手账感信息卡 + 标签化食材。
- 文字：短句、亲切、强调“好吃”和“容易做”。
- v2 复杂菜：主图占比应更克制，参考厨房操作台风比例；保留暖色和分享感，把更多空间留给食材、步骤和过程态图示。

### 2. 米其林菜单风

- 气质：高级、克制、留白、餐厅菜单感。
- 适用：精致菜、西餐、宴客菜、摆盘型菜品。
- 构图：大留白、精致主图、风味结构和烹饪节奏。
- 文字：克制、准确、像菜单说明，不要过度口语化。

### 3. 厨房操作台风

- 气质：实用、清晰、可照做、高信息密度。
- 适用：家常硬菜、新手教程、步骤关键的菜。
- 构图：清单表格 + 步骤流程 + 火候提示。
- 文字：明确用量、火候、时间、状态判断。

### 4. 苹果 Bento 风

- 气质：现代、干净、发布会感、一眼读懂。
- 适用：精品菜谱、一览图、产品化展示。
- 构图：Bento Grid，主图大卡 + 信息卫星卡 + 步骤脊柱。
- 文字：短而有力，避免说明书式长段。

## 输出约束

- 直接输出 HTML，从 `<!DOCTYPE html>` 到 `</html>`。
- 不要输出 markdown fence。
- 不要解释生成过程。
- 所有文本不得溢出卡片；必要时减少字数、分栏或缩小局部字号。
